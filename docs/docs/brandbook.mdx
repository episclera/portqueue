# Brandbook

PortQueue's dashboard and docs share one calm, muted visual system. The goal is a
content-first surface: a dominant neutral, a single desaturated green accent, one text
colour, and low-contrast semantic colours used **only where they carry meaning**.

All colours, radii, shadows, type stacks and motion come from one set of design tokens:
[`packages/theme/src/tokens.json`](https://github.com/episclera/portqueue/blob/main/packages/theme/src/tokens.json),
published inside the repo as the private `@portqueue/theme` package. It has no components and no
React — each surface keeps its own toolkit and takes only its look from the tokens:

- **The dashboard** renders with [antd](https://ant.design), and maps the tokens onto antd's theme
  config in one file (`packages/dashboard/src/client/theme.ts`).
- **These docs** render with Docusaurus, and point Infima's variables at the tokens'
  CSS variables (`src/css/custom.css`).

The JSON is the only place a value is written. The package exports it three ways: the raw
`tokens.json`, a typed `tokens` object for JavaScript, and `theme.css`, which sets every token as
a `--pq-*` custom property (light by default, dark under `data-theme="dark"`). `theme.css` is
generated from the JSON by `npm run build -w @portqueue/theme`, and lint fails if the two
disagree. Change a token in the JSON, rebuild, and both surfaces follow.

The swatches below read their values from the package too, so this page can't drift from it.

## Semantic palette

Muted and desaturated to match the core palette — **never** saturated/pure red, orange or
blue. Use them only when the context genuinely means it; never decoratively. Always pair
with `--pq-color-text` (dark) for on-colour text, never white.

## Iconography

Icons are real SVGs from [`@ant-design/icons`](https://ant.design/components/icon) (v6) —
**never emoji**. Emoji render as a different picture on every platform, carry colours that
aren't in the palette, and can't inherit the theme, so they are not used anywhere in the
dashboard or these docs.

- **One curated set in the dashboard.** The dashboard re-exports the icons it uses from
  `packages/dashboard/src/client/icons.ts` under intent-named aliases — `RetryIcon`,
  `PauseIcon`, `RemoveIcon`, `SearchIcon` — and its components import from there, never from
  `@ant-design/icons` directly (lint enforces it). Adding an icon means adding a line to that
  file, which keeps the bundle to what's actually used and stops the same idea being drawn two
  ways. These docs import the icon package directly — they use a handful, and the light/dark
  toggle uses the same two glyphs as the dashboard's.
- **One icon per action.** The dashboard's action icons live in one map
  (`constants/labels.tsx`), so Retry is the same glyph in a row, a bulk menu and a detail
  header.
- **Icons inherit.** Every icon is sized in `em` and filled with `currentColor`, so it takes
  the size and colour of the text beside it. Colour an icon only where the colour carries the
  same meaning the palette gives it — semantic tones on alerts and toasts, `--pq-color-danger` on
  a destructive action.
- **Decorative by default.** An icon beside a text label is `aria-hidden`; an icon-only
  control carries the name in `aria-label` (and usually a tooltip).

## Feedback & affordances

A control that changes nothing visible has not told the user anything. The dashboard takes these
from antd rather than building its own, so every surface behaves the same way.

- **An action confirms itself.** Copying a job id (antd's `Typography` `copyable`) swaps the icon
  for a tick and the tooltip for "Copied". Never let a copy look identical before and after.
- **Every mutation reports its outcome** in a toast (antd's `message`) — including the partial
  ones: "Removed 3 of 5 jobs." rather than a success that claims all five.
- **A link looks like a link.** Anything that takes the user to another page — a job, queue,
  schedule or instance named in a table, a header or a detail card — renders as a link in the
  link colour, never as a tag or a code chip. A value styled as a tag reads as a label, so nobody
  thinks to click it. A long id stays truncated; the full value is on hover. In the dashboard that
  link is `AppLink` (antd's `Typography.Link`, routed through the app).
- **Every tag has an edge.** A tag or badge always has a 1px border in exactly its text colour,
  over a much lighter tint of that colour, so the text reads and the shape is clear on any
  surface. No borderless fills, and no border paler than the text.
- **A state is a coloured tag.** Every status or state — a job's status, a queue's or instance's
  pause state, liveness, whether a schedule is enabled — renders as a tag, in tables, page headers
  and detail cards alike, and its colour says what it means: green is healthy and working, amber
  is deliberately held back, red is refusing work, grey is inactive. Job statuses use the status
  palette. A tag is never a link (see above), and a state is never plain text.
- **A detail page's header names the record.** A small grey line says what it is (`Job`,
  `Queue`, `Schedule`, `Instance`), the next line gives its full id or name in bold — never
  truncated — with its state tags beside it.
- **Explanations are visible.** When a statistic card needs explaining, the tooltip hangs off an
  info icon after the card's title (hover or keyboard focus), never off a hover over the whole
  card — a tooltip nobody can see is there is a tooltip nobody reads.
- **Clipped content scrolls.** A table wider than its card scrolls sideways inside it rather than
  squeezing its columns, so a timestamp never wraps mid-value.

## Usage rules

- **Neutral dominates.** `--pq-color-bg` covers the majority of every screen.
  `--pq-color-brand` is an accent — buttons, active nav/tabs, links, positive indicators — never a big background.
- **One text colour.** `--pq-color-text` for everything; drop to ~60–75% opacity for
  secondary/muted text. No warm greys, no pure black, no white body text.
- **Contrast first.** Because the accents are light and muted, on-colour text is always the
  dark `--pq-color-on-brand`, not white — this keeps every combination at WCAG AA. Light green
  is used for _fills_; `--pq-color-link` (the darker green on light surfaces, the lighter one on
  dark) is used for green _text/links_.
- **Semantics carry meaning.** `--pq-color-danger`/`--pq-color-warning`/`--pq-color-info` appear
  only where they mean something — never for decoration.

### On the dashboard

The brand green for primary CTAs and the selected navigation item; danger for failed jobs and
destructive actions; warning for threshold alerts and paused states. Job states use the status
palette (`tokens.status`), one colour per state everywhere a state is shown. Tables stay on the
surface colour with border-coloured separators, so semantic colours stand out only where they're
meaningful.

### In these docs

`--pq-color-bg` for content, `--pq-color-surface-alt` for code blocks, `--pq-color-link` for
links. Admonitions always sit on a plain white (`--pq-color-surface`) banner — **no coloured
fill** — and only the **title** takes a semantic colour: `--pq-color-info-text` blue for
`:::info`, `--pq-color-warning-text` orange for `:::warning`/`:::caution`,
`--pq-color-danger-text` red for `:::danger`. `:::note` stays neutral. Green is
never used for a banner.

:::info Info
Informational callouts use a blue title on a white banner.
:::

:::note Note
Plain asides use a neutral title — no accent colour.
:::

:::warning Warning
Caution/deprecation admonitions use the muted `--warning` orange title.
:::

:::danger Breaking change
Critical/breaking admonitions use the muted `--pq-color-danger-text` red title.
:::
