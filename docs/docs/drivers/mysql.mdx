# MySQL driver

For teams shipping on MySQL 8+. Uses `FOR UPDATE SKIP LOCKED` for contention-free
claiming. MySQL has no `RETURNING` and no `LISTEN/NOTIFY`, so the driver mutates then
reads the affected rows back inside the same transaction, and workers wake via polling.

## Connect

```ts
import { PortQueue } from '@portqueue/core';
import { MysqlDriver } from '@portqueue/core/drivers/mysql';

const pq = new PortQueue({
  driver: new MysqlDriver({
    connectionString: process.env.MYSQL_URL,
    // or share an existing mysql2 pool: { pool }
    // or pass raw mysql2 config: { config: { host, user, password, database } }
  }),
});
await pq.init();
```

## Capabilities & notes

- **`FOR UPDATE SKIP LOCKED`** — yes (MySQL 8.0+), for contention-free claiming.
- **`RETURNING`** — no. The driver mutates then reads the affected rows back in the same
  transaction, so claims and inserts stay atomic without it.
- **`LISTEN/NOTIFY`** — no. Core uses polling for wake-ups; tune `pollIntervalMs` to your
  latency budget.
- **Transactional enqueue** — pass a `tx` from a query-builder/ORM adapter that speaks
  `mysql2` (e.g. `fromKnex`, `fromKysely`, `fromDrizzle`, `fromSequelize`). See
  [Transactions](../guides/transactions.mdx).

:::tip Optimization
Requires MySQL 8.0+ for `SKIP LOCKED`. Size the pool for the sum of worker
concurrencies, keep handler transactions short, and turn on
[retention](../guides/retention.md) so the `job` table stays lean.
:::
