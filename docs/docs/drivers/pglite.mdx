# PGLite driver

An **embedded Postgres** (WASM) — real Postgres semantics with no server to run. Ideal
for local development, tests, and single-process apps that want Postgres behavior.

## Install

<PackageManagerTabs pkg="@portqueue/core @electric-sql/pglite" />

## Connect

```ts
import { PortQueue } from '@portqueue/core';
import { PgliteDriver } from '@portqueue/core/drivers/pglite';

// in-memory (great for tests) or a persisted data dir
const pq = new PortQueue({ driver: new PgliteDriver({ dataDir: 'memory://' }) });
await pq.init();
```

## Capabilities & notes

- Postgres-compatible SQL, including `SKIP LOCKED` and `RETURNING`.
- **Single-process** by design — it runs in your Node process, so it is not for
  multi-instance coordination. Cross-instance `LISTEN/NOTIFY` doesn't apply; core uses a
  polling loop within the process.
- Its wire-compatibility makes it the backbone of the PortQueue **test suite** (with SQLite).

:::tip Optimization
Use `memory://` for fast tests; persist to a `dataDir` when you want durability on a
single node. For anything multi-instance, use [Postgres](./postgres.mdx).
:::
