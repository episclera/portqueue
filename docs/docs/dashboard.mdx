# Dashboard

`@portqueue/dashboard` is a pluggable React ops dashboard — queues, jobs, workflow runs,
schedules, instances, and live stats — served from the CLI or mounted on your existing HTTP
server.

## Pages

- **Overview** — KPI cards, per-queue table with pause/resume, throughput trend, and an
  instances summary.
- **Instances** — every registered instance with liveness, per-instance job counts, and
  per-instance pause/resume (only populated for servers that set an [instance key](./scale-horizontally.md#give-each-server-an-identity-key)).
- **Schedules** — recurring definitions across queues.
- **Queue / Job detail** — drill into a queue's jobs or a single job/workflow run.

## Mount on an existing app

Create the dashboard once from your running PortQueue, then mount it with the adapter for
your framework — Express, Koa, Fastify, NestJS, or raw Node all ship in the box:

```ts
import { createDashboard } from '@portqueue/dashboard';

const dash = createDashboard({
  portQueue: pq,
  basePath: '/portqueue',
  auth: { mode: 'basic', username, password },
});
```

## Serve it from the CLI (no app changes)

If you'd rather not touch your app, the CLI hosts the dashboard as a standalone process —
it imports your [config module](./cli.md#the-config-module) and serves the same UI:

```bash
portqueue dashboard --config ./portqueue.config.ts --port 9000 \
  --root-user admin --root-password ****
```

## Securing

- **Basic auth** via the `auth` option (shown above).
- **Custom auth** — provide your own middleware/guard for SSO or session checks.
- Always mount it behind your platform's auth in production, and rely on parameterized queries.

## Docker

You don't need to containerise your app to run the dashboard — the CLI image can host it
as its own service. Mount your [config module](./cli.md#the-config-module), pass `--config`,
and expose the dashboard `--port`. Because everything is driven by the shared config, no app
changes are needed and the same image doubles for one-off ops (migrations, purges, …).

```dockerfile title="Dockerfile"
FROM node:34-alpine
WORKDIR /app

# Install the CLI plus the client for your driver — it's an optional peer dependency,
# so pick the one you use: pg (Postgres), mysql2, oracledb, …
RUN npm install -g @portqueue/cli pg

# The config module is mounted at runtime (see `docker run` below), so nothing
# app-specific is baked into the image.
EXPOSE 9000
ENTRYPOINT ["portqueue"]
# Default to serving the dashboard; override the command for one-off ops.
CMD ["dashboard", "--config", "/config/portqueue.config.mjs", "--port", "9000"]
```

```bash
# Build the image once.
docker build -t portqueue-cli .

# Host the dashboard: mount your config, publish the port.
docker run --rm -p 9000:9000 \
  -v "$(pwd)/portqueue.config.mjs:/config/portqueue.config.mjs:ro" \
  portqueue-cli

# One-off op: override the default command (the ENTRYPOINT stays `portqueue`).
docker run --rm \
  -v "$(pwd)/portqueue.config.mjs:/config/portqueue.config.mjs:ro" \
  portqueue-cli migrate --config /config/portqueue.config.mjs
```

:::note
Point `--config` at a prebuilt `.js`/`.mjs` module — see
[The config module](./cli.md#the-config-module) for loading a `.ts` config under a loader.
:::
