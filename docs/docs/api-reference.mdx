## Worker

A consumer registration from `pq.createWorker(options)`. It starts claiming automatically after
`pq.init()` and stops on shutdown — **there are no lifecycle methods**. Control processing through
the `Queue` (`pause`/`resume`) and observe it through `pq.on(...)`. All consumer settings live on
[WorkerOptions](#workeroptions).

## Options

Every duration in every options bag below is a number of **seconds** — there is no duration string to
parse, no other unit anywhere in the API, and exactly one option per setting (no `Date`-shaped
alternative to a delay). Names carry the unit (`expireInSeconds`, `lockDurationSeconds`, …) so a call
site can't be misread.

A duration describing a **job** — `expireInSeconds`, `retry.delaySeconds`, `maxDelaySeconds`,
`ttlSeconds`, `startAfterSeconds`, `startEverySeconds`, `rateDurationSeconds` — must be a **whole**
number of seconds: it is stored in an integer column, so a fraction is rejected rather than
truncated. The process-local loop cadences that are never stored — `tickIntervalSeconds`,
`pollIntervalSeconds`, `lockDurationSeconds`, `heartbeatIntervalSeconds`, `sampleIntervalSeconds`,
`maxEventLoopDelaySeconds`, `timeoutSeconds` — accept fractions, since sub-second timer intervals
and thresholds are meaningful there.

### PortQueueOptions

The single argument to `new PortQueue(...)`.

| Option                | Type                                            | Default        | Description                                                                                                 |
| --------------------- | ----------------------------------------------- | -------------- | ----------------------------------------------------------------------------------------------------------- |
| `driver`              | `Driver`                                        | — **required** | A driver instance (see [Drivers](#drivers)).                                                                |
| `logger`              | `Logger \| LoggerOptions`                       | console logger | A logger you supply, or `{ level?, pretty? }` for the built-in one.                                         |
| `migration`           | `MigrationMode`                                 | `AUTO`         | `AUTO` (apply pending on init), `MANUAL` (call `migrate()` yourself), or `VALIDATE_ONLY` (fail if pending). |
| `instance`            | [`InstanceOptions`](#instanceoptions)           | —              | This process's identity & heartbeat.                                                                        |
| `systemLimiter`       | [`SystemLimiterOptions`](#systemlimiteroptions) | —              | Pressure thresholds that pause claiming. Omitted by default, so nothing throttles.                          |
| `tickIntervalSeconds` | `number`                                        | `5`            | Scheduler / retention / monitor tick interval, in seconds.                                                  |

### ShutdownOptions

| Option           | Type      | Default | Description                                                                                                                                                |
| ---------------- | --------- | ------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `graceful`       | `boolean` | `true`  | Let in-flight handlers finish before disconnecting.                                                                                                        |
| `timeoutSeconds` | `number`  | `30`    | Max time, in seconds, to wait for a graceful drain, and for background work (maintenance tick, heartbeat, notify) to finish before the driver disconnects. |

### InstanceOptions

| Option                     | Type     | Default   | Description                                                                                                                                             |
| -------------------------- | -------- | --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `instanceKey`              | `string` | anonymous | Stable, human-meaningful name for this process (e.g. `'worker-eu-1'`). Naming it lets you target, list, and pause it; unnamed processes still run jobs. |
| `heartbeatIntervalSeconds` | `number` | `15`      | How often the instance row's `last_seen_at` is refreshed, in seconds.                                                                                   |

### SystemLimiterOptions

**Passing this object is what turns backpressure on.** Every worker on the client then stops
claiming while any threshold you set is breached, and resumes once every watched metric has fallen
to `resumeHysteresis` of its own limit. There is no per-worker opt-in: define a `systemLimiter` and
they all respect it, omit it (the default) and none do.

Only the thresholds you set are checked, and there are no defaults to merge with — `{}` samples but
can never throttle. Durations here may be fractional, since they are in-process sampling knobs
rather than stored values.

The **machine's** CPU and memory are measured **regardless** — the instance heartbeat records them,
so the dashboard can show the health of each host, and there is no option to switch that off. Both
are host-wide shares (`os.cpus()` time deltas and `os.totalmem()`/`os.freemem()`), not this Node
process's usage, so two instances on one box report the same figures. Event-loop delay is the
exception on both counts — it is this process's, and measuring it means keeping a `perf_hooks`
histogram enabled, so it is only sampled once `maxEventLoopDelaySeconds` gives it a purpose. See
[Rate limiting & backpressure](./guides/rate-limiting.md#every-systemlimiter-option).

| Option                     | Type     | Default                     | Description                                                              |
| -------------------------- | -------- | --------------------------- | ------------------------------------------------------------------------ |
| `sampleIntervalSeconds`    | `number` | `2`                         | How often to sample system metrics, in seconds.                          |
| `maxEventLoopDelaySeconds` | `number` | `0.2` (default config only) | Mean event-loop delay above this, in seconds, counts as pressure.        |
| `maxCpuPercent`            | `number` | unset                       | Machine CPU busy share (0–100) above this counts as pressure.            |
| `maxMemoryPercent`         | `number` | unset                       | Machine used memory (0–100 of total) above this counts as pressure.      |
| `resumeHysteresis`         | `number` | `0.8`                       | Fraction (0–1) below the threshold metrics must fall to before resuming. |

## Result types

Reads return objects, never bare ids. The main shapes:

- **AddJobResult** — `jobId?`, `scheduleId?`, `nextRunAt?`, `queue`, `status?`, `deduplicated`, `deduplicationReason?`, `startAfter?`.
- **JobSnapshot** — the full read-side view of a job (all timestamps as `Date`, plus a derived `stalled` flag).
- **ScheduleInfo** — `scheduleId`, `cron?`, `everySeconds?`, `timezone?`, `nextRunAt?`, `lastRunAt?`, `enabled`, `idempotencyKey?`.
- **QueueInfo** — `name`, `processingPaused`, `acceptingPaused`, `counts`, `inUse`.
- **InstanceInfo** — `instanceKey`, `processingPaused`, `alive`, `createdAt`, `updatedAt`, `lastSeenAt`, `counts`.
- **QueueStats** — `queue?`, `counts` (a `JobStatus` → count map).
- **Page&lt;T&gt;** — `items`, `cursor`, `hasMore`, `total` (rows matching the query, ignoring paging).

## Errors

Every error thrown by `@portqueue/core` is an instance of `PortQueueError` (or a subclass) and
carries a `.code` ([`PortQueueErrorCode`](./troubleshooting.md)) and a `.context` object. All are
importable from `@portqueue/core`, so you can branch with `instanceof`:

`PortQueueError` (base) · `NotStartedError` · `InvalidOptionsError` · `UnsupportedCapabilityError` ·
`SchemaVersionMismatchError` · `MigrationFailedError` · `DriverConnectionError` · `DriverQueryError` ·
`JobNotFoundError` · `QueuePausedError` · `QueueInUseError` · `InstanceActiveError` ·
`ShutdownTimeoutError` · `MissingPeerDependencyError`.

The full error table — codes, causes, and remedies — lives in [Troubleshooting](./troubleshooting.md).
